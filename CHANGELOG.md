# Changelog

Пользовательские описания релизов. Именно ЭТОТ файл (не заголовки коммитов) показывается в уведомлении об обновлении: раздел на версию, пункты — строки, начинающиеся с «- ». Заполняется ПЕРЕД тегированием релиза — scripts/release.sh откажется публиковать версию без её раздела здесь. Коммиты остаются техническими и пользователям не показываются.

## 0.6.4 — 2026-09-17

- Обновления больше не залипают: кнопка «Обновить» переставала работать навсегда, если предыдущая попытка была прервана (перезагрузка, нехватка памяти) — теперь забытый признак распознаётся и не мешает; «✅ Обновлено» приходит только после реально удавшейся сборки и запуска
- Обновление безопаснее и надёжнее: подпись релиза проверяется ДО того, как новые файлы попадут на диск, при любой неудаче версия откатывается на прежнюю; если на GitHub нет подписанного релиза — мост берёт его с зеркала (раньше в этом случае обновления вставали намертво); проверка «контейнер поднялся» больше не принимает контейнер, падающий по кругу
- Если сервер ходит в Telegram через прокси, сообщения об обновлении наконец доходят — раньше весь процесс, включая отказы, шёл в полной тишине
- Сборка при обновлении: секунды вместо минут и без разрастания диска — тяжёлый слой с Chromium перестал пересобираться на каждом коммите
- Автообновление теперь обслуживает ВСЕ мосты на сервере: один таймер обходит список установок вместо одного выбранного каталога (раньше второй мост молча отбирал автообновление у первого, и то же делал обычный заход в меню настроек). Если автообновления нет вовсе (setup.sh запускали не от root), кнопка «Обновить» прямо говорит об этом, а не обещает несбыточное
- Несколько мостов на одном сервере: второй ставится в свой каталог (INSTALL_DIR=/opt/telemax-2), имя контейнера фиксируется явно, установка второго не предлагает погасить чужой контейнер
- Личная переписка защищена: /deletegroup в теме личного чата теперь прямо предупреждает, что удалит её и у собеседника, называя человека по имени; остальные групповые команды в личном чате отвечают понятным отказом вместо невнятной ошибки MAX
- Мост больше не кирпичится: повреждённый файл сессии MAX не уводит контейнер в вечный перезапуск — мост поднимается и просит /login
- Спецсимволы в пароле прокси ($, пробел, &) больше не ломают установку и обновления: раньше Docker молча искажал такое значение и Telegram просто не подключался
- «📊 Статус» больше не сообщает «актуальная версия», когда проверить обновления не удалось

## 0.6.3 — 2026-09-11

## 0.6.0 — 2026-09-11

- Пульт: кнопка «📊 Статус» — версия, аптайм, состояние MAX и Telegram, когда прошли последние сообщения в каждую сторону, диск/RAM/нагрузка сервера, доступность обновления
- Пульт: поделитесь в общей теме группы контактом из Telegram — бот найдёт его в MAX по номеру и предложит начать чат (автоматически сопоставлять с вашей книгой контактов Telegram бот не может — Bot API не даёт такого доступа)
- Установка (setup.sh): проверка токена с показом имени бота, ручной ввод id группы, проверка группы — темы включены, бот администратор с «Управлением темами» — с понятным списком того, чего не хватает
- Установка (install.sh): лог в /var/log/telemax-install.log, предварительная проверка сервера (ОС, диск, RAM, сеть, время), ожидание фонового обновления apt, запасной путь установки Docker
- /kill: честно про сессию — завершить её на стороне MAX снаружи нельзя; после /kill завершите её в приложении MAX (Настройки → Устройства)
